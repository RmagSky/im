升版规则

提交前按改动性质判定改哪一位，判定不清时按高一级处理。

改动性质版本号变动判定标准
功能变更中间位 +1增删页面、增删功能单元、增删章节或分组；尾数归零。例：v1.0.3 → v1.1.0
内容变更尾数 +1规则口径、交互流程、字段集合、页面名单、术语定义、优先级调整。例：v1.0.1 → v1.0.2
样式微调版本号不变文案措辞、错别字、字号配色、元素位置、注释整理。照常交付，不写变更记录行
升版只替换当前版本展示位与本表首行，历史行保持原样。禁止全局替换版本号字符串，该操作会连带改写历史记录行。

多人同时升版的处理顺序

两人各自动手升版时，版本区与记录表必然冲突。按以下顺序收口，不并行处理。

1
先合功能，版本区不动
合并冲突时保留双方功能改动，版本展示位与记录表暂不修改。功能全部合入后再统一收口。
2
以合入后的版本为基数升版
取合入后的最新版本号作为基数，按本次改动性质加一位。自己分支上原有的版本号作废，两个版本号不并存。
# 合入后版本为 v1.0.3，本次为功能变更
v1.0.3  →  v1.1.0
3
记录表只加自己的一行
保留上游全部历史行，只在自己新版本对应的首行写入本次内容。上游已发布的行不改写、不删除。

2.1 页面栈与导航

页面以栈结构管理，进入即入栈，返回即出栈。一级 Tab 切换重置栈。

栈规则

规则项约定
进入二级页当前页压入栈，新页自右向左推入，入场动画见 3.4
返回栈深 ≥2 时生效，顶层页向右滑出并卸载；栈深为 1 时返回按钮无响应
一级 Tab 切换清空栈并重建，Tab 之间不保留返回关系
深链进入栈固定为「对话列表 → 目标页」两级，返回落回对话列表
滚动位置入栈时记录当前页滚动位置，返回后恢复
页面标题导航栏居中，17px / 600；右侧动作位宽 56px，左侧返回位同宽以保持标题居中

2.2 浮层与反馈

浮层四类，同时只存在一个。任一新浮层打开前先关闭既有浮层。

类型形态关闭方式
对话框宽 268px，圆角 15px，居中；标题 17px 加粗，说明 13px点遮罩关闭；按钮按顺序横排，取消居左，危险动作标红
动作面板底部上滑，圆角 14px，条目 17px 居中，末项「取消」独立成块点遮罩、点取消关闭
长按菜单附于气泡左侧，圆角 12px，条目含文字与图标，最大 6 项点菜单外任意区域关闭；打开后 60ms 起监听外部点击，避免同一次长按立即关闭
轻提示底部 96px 居中，深色胶囊，白字 13px1600ms 自动消失；新提示替换旧提示，不叠层
破坏性操作一律二次确认，按钮文案用动作本身（删除、退出、注销），不使用「确定」这类无指向文案。

2.4 消息操作链路

链路从长按开始，六项操作分三条出口：单条动作、多选动作、转发动作。

长按唤出

项约定
触发按住气泡 460ms；移动、抬起、取消即撤销；右键等效触发
失效条件处于多选态时不响应长按
菜单项置顶、引用、转发、多选、复制、删除，顺序固定

三条出口

1
置顶、复制
置顶以轻提示确认「已置顶该消息」；复制写入剪贴板，浏览器拒绝授权时静默失败，不弹错误。
2
引用
引用内容写入输入区上方引用条，可点叉取消；发送后生成引用气泡，引用条清空。
3
转发与多选
转发直接进入转发页；多选进入勾选态，右上改「取消」，底栏出现转发与删除两项。
# 多选态
勾选消息 → 转发 → 转发页选择目标 → 确定 → 轻提示「已转发给 N 个会话」
勾选消息 → 删除 → 二次确认「确定删除已选的 N 条消息？」 → 即时移除
多选态下长按菜单失效、单条点击只切换勾选状态。未选中任一条时点转发或删除，仅提示「请先选择消息」，不进入下一步。

2.5 软键盘

键盘为原型内置的 iOS 样式面板，非系统输入法，用于还原真实输入体验与截图口径。

项约定
唤起输入框获得焦点即弹出，消息区滚到底部
收起点击键盘、输入框、更多面板以外的区域收起
字符层字母层与数字层切换；shift 一次性生效，输入一个字符后自动回落
光标按键操作不夺焦点，插入位置跟随真实光标；选区变化时同步光标位置
发送回车发送当前草稿；草稿在页面刷新后保留
输入框属性关闭自动大写、自动纠错、自动填充，inputmode="none" 抑制系统键盘弹出

4.1 条款生效范围

强制条款
第 4 章是团队协作的约定，与原型文件同时生效。参与原型更新、评审、发布的每个人按本章执行；本章条款的调整按功能变更处理，升版并在 1.1 留记录。
适用对象约束内容
文件职责划分proto.html 只承载界面与交互；rule.html 是本文件，承载规则与口径；index.html 只承载切换逻辑。规则文本不进原型页，原型页不放规则说明
改动前拉取上游最新提交，确认本次改动范围不与上游重叠
改动中按第 2、3 章规范落实现，新规则先写入本文件再改原型
改动后本地逐页验证，按 4.6 清单自查，按 4.5 格式提交
本章变更条款调整视为功能变更，同步升版并在 1.1 记录，不静默修改

4.3 五步流程

每次改动按顺序走完五步，不跳步、不并步。以下指令在仓库根目录执行。

1
拉取上游
动手改文件之前先取远端最新提交。本地有未提交改动时，先提交或暂存，再拉取。
# 取远端并以 rebase 方式并入本地提交
git pull --rebase origin main
2
检查新提交
确认上游改了哪些文件、是否与本次改动重叠。重叠部分先读懂对方的改法，再定自己的改法。
# 本地落后的提交
git log --oneline HEAD..origin/main

# 上游改了哪些文件
git diff --stat HEAD origin/main

# 逐行查看具体改动
git diff HEAD origin/main -- proto.html
3
合并
把上游提交并入本地，使本地同时包含双方改动。第 1 步已用 --rebase 时，此步只确认结果。
# 直接合并时执行
git merge origin/main

# 确认只剩自己的改动
git status
git log --oneline -8
4
处理冲突
按 4.4 逐段判定保留哪一侧，不整文件取一边。修正后标记解决并继续。
# 查看冲突文件
git status

# 修正后标记为已解决
git add proto.html rule.html

# rebase 过程继续；merge 过程改为 git commit
git rebase --continue
冲突标记 <<<<<<< / ======= / >>>>>>> 须全部清除。残留标记会让整页脚本失效，页面白屏。
5
上传更新
本地验证通过、4.6 清单逐项确认后推送，推送后核对两个入口。
# 暂存并提交，提交信息按 4.5 格式
git add -A
git commit -m "feat(chat): 消息菜单增加举报入口"

# 上传到主线
git push origin main

# 确认本地与远端一致
git status

4.4 冲突处理规则

同一处被两人改动时按位置判定，逐段处理，不整文件取一侧。

冲突位置处理方式
页面结构（PAGES.*）双方新增页面全部保留，按 1.2 的 Tab 归属归位，页面 ID 不重名；重名时后者改名并同步改 1.2 清单
样式令牌（:root）色值取上游；字号、圆角、间距取上游。新增令牌双方都保留，命名冲突时用更具体的语义名
交互处理（ACT.*、事件监听）同一动作被两处实现时取上游版本，把另一方的行为合并进同一函数，不留两份实现
演示数据（D 对象）保留上游数据集，自己的样例另加条目，不覆盖上游已有条目；改条数时同步改 1.2 数据表
规范章节（rule.html）同一条款两处表述时取语义更完整的一份，另一份的内容并入，不并列两段
版本号与变更记录合并阶段不处理，功能全部合入后按 1.1「多人同时升版的处理顺序」一次性收口
框架页（index.html）切换逻辑改动取上游；新增视图（Tab）双方都保留，插入 VIEWS 数组并同步改深链解析
判定不了保留哪一侧时，先问改动方，不自行删除他人提交。合并后逐页打开验证，不以「看起来没错」作为通过标准。

4.5 提交信息格式

一行摘要写清改了什么，类型用英文前缀，范围写页面或文件。

# 格式：类型(范围): 摘要
feat(chat): 消息菜单增加举报入口
fix(proto): 修复软键盘收起后输入框失焦
style(appearance): 气泡色块尺寸对齐 8px 网格
docs(rule): 补充冲突处理中的交互处理条款
chore: 移除临时截图文件
类型适用改动
feat新增页面、功能单元、章节、浮层
fix修复错误：交互失效、样式错位、状态不同步
style字号、配色、间距、位置等视觉调整，不升版
docs本规范文档、README 的文字改动
chore部署配置、忽略文件、清理临时文件

4.7 禁止事项

禁止操作原因与替代做法
强制推送git push --force 覆盖他人提交。改用 --force-with-lease，且仅限自己刚推送、无人接着改的分支
改写已推送的提交已推送的提交不改写、不压缩。需撤销时用新提交反向修改
不拉取就改共享文件proto.html 被全组共用，改前必拉取，改后必逐页验证
规则只写进原型规则文本的唯一载体是 rule.html。原型内只留界面与提示文案
以截图为唯一依据改样式色值、字号、圆角一律取 3.1–3.3 的令牌，不按目测取值
把 mock 数据当接口原型不含后端，页面不接真实环境，演示数据只在 D 对象内
提交前不做本地验证未通过 4.6 清单的改动不进 main
